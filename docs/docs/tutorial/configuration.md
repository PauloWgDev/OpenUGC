# Configuration

OpenUGC reads all its settings from **environment variables**. This page lists every one of them, what it does, and when you need it.

How you set them depends on where you run the API:

- **Docker Compose:** in the `environment` section of the `open-ugc` service.
- **Run scripts:** in `run.ps1` or `run.sh` (see [Self-Hosting OpenUGC](./self-host-setup/host-api.md)).
- **Render or another host:** in the service's environment settings.

---

## Required Settings

The API won't start without these.

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_PROFILE` | Which database you use. Only `postgres` is supported for now | `postgres` |
| `DATABASE_URL` | JDBC connection URL of the PostgreSQL database | `jdbc:postgresql://localhost:5432/openugc` |
| `DATABASE_USERNAME` | Database user | `postgres` |
| `DATABASE_PASSWORD` | Database password | `mypassword` |
| `JWT_SECRET` | Secret used to sign the login tokens. At least 32 bytes. The API refuses to start if it's missing, too short, or still `CHANGE_ME` | output of `openssl rand -base64 48` |
| `STORAGE_TYPE` | Where uploaded files are stored: `local` (a folder on the disk) or `cloud` (Google Cloud Storage) | `local` |

---

## Storage Settings

### Local storage (`STORAGE_TYPE=local`)

| Variable | Description | Example |
|----------|-------------|---------|
| `STORAGE_LOCATION` | Folder where the files are saved. It's created if it doesn't exist | `/var/lib/openugc/storage` |

Make sure this folder survives restarts and updates. With Docker, mount it as a volume (the compose example already mounts `./storage`). Don't use local storage on hosts with a temporary disk, like Render's free plan.

### Google Cloud Storage (`STORAGE_TYPE=cloud`)

| Variable | Description | Example |
|----------|-------------|---------|
| `CLOUD_BUCKET` | Name of the bucket | `openugc-bucket` |
| `GOOGLE_APPLICATION_CREDENTIALS` | Path to the service account JSON key | `/etc/secrets/openugc-key.json` |

See [Host with Google Cloud Storage](./third-party-setup/host-storage.md) to create the bucket and the key.

### How files are stored

- Each uploaded file gets a random name generated by the server (the original file name is only used for its extension). Files are never overwritten.
- Players never get a direct link to the storage. The API serves the files through `/api/v1/content/download/{id}` and `/api/v1/content/thumbnail/{id}`, so local storage and Google Cloud Storage work the same way for your game.

## Optional Settings

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `8080` | Port the API listens on. Hosts like Render set it automatically |
| `GUEST_ENABLED` | `true` | Allows `POST /api/v1/auth/guest`, which gives guest tokens. See [Guest Login](../documentation/Authorization/guest.md) |
| `GUEST_CANPOST` | `false` | Allows guests to upload content. Only works if `GUEST_ENABLED` is `true` |
| `CORS_ALLOWED_ORIGINS` | `*` | Which websites can call the API from a browser. See [CORS](#cors-for-webgl-and-browser-clients) |
| `MAX_PAGE_SIZE` | `100` | Largest `size` a client can ask for in the content, user and rating lists. Bigger values return `400`. See [Pagination](../documentation/api-basics.md#pagination) |
| `SERVER_TOMCAT_REMOTEIP_INTERNAL_PROXIES` | private IP ranges | Which reverse proxies are trusted to tell the real client IP. See [Running behind a reverse proxy](#running-behind-a-reverse-proxy) |
| `SPRING_SERVLET_MULTIPART_MAXFILESIZE` | `1MB` | Maximum size of each uploaded file |
| `SPRING_SERVLET_MULTIPART_MAXREQUESTSIZE` | `1MB` | Maximum size of a whole upload request (file + thumbnail + metadata) |

If you turn guests off with `GUEST_ENABLED=false`, no new guest tokens are given, but the guest tokens that already exist keep working until they expire (up to 24 hours).

---

## Upload Size Limit

By default, an upload can be at most **1 MB in total**, counting the file, the thumbnail and the metadata together. Bigger requests are rejected with `413 Payload Too Large`.

If your content is bigger (levels, mods, skins with textures...), raise both limits. For example, to allow 50 MB:

```
SPRING_SERVLET_MULTIPART_MAXFILESIZE=50MB
SPRING_SERVLET_MULTIPART_MAXREQUESTSIZE=50MB
```

If you use a reverse proxy, it may have its own limit too (nginx allows 1 MB by default, with `client_max_body_size`).

## CORS (for WebGL and Browser Clients)

Browsers only let a web page call the API if the API allows that page's origin. This matters for **Unity WebGL builds**, web launchers and any website that uses the API. Native builds (Windows, Android, consoles...) and servers are not affected.

`CORS_ALLOWED_ORIGINS` takes a comma-separated list of origins. Each one can be an exact origin or a pattern with `*`:

```
CORS_ALLOWED_ORIGINS=https://mygame.com,https://*.itch.zone
```

- The default, `*`, allows every origin. This is safe here, because the API uses tokens in the `Authorization` header and not cookies, so another website can't use your players' sessions.
- An empty value turns CORS off. Use it if no browser client will ever call the API.

---

## Running Behind a Reverse Proxy

If the API runs behind a reverse proxy or load balancer (nginx, Caddy, Render, and so on), every request reaches the API from the proxy's IP. The real client IP comes in the `X-Forwarded-For` header.

OpenUGC uses the client IP for the [rate limits](../documentation/api-basics.md#rate-limits) and to record downloads. It only trusts `X-Forwarded-For` when the request comes from a trusted proxy. By default these are the private network ranges (like `10.x.x.x`, `192.168.x.x` and `127.0.0.1`), which covers most setups, including Render and a proxy on the same machine.

If your proxy connects from a public IP, set `SERVER_TOMCAT_REMOTEIP_INTERNAL_PROXIES` to a regular expression that matches its IP, for example:

```
SERVER_TOMCAT_REMOTEIP_INTERNAL_PROXIES=203\.0\.113\.10
```

Without this, all players would share the proxy's IP, and they would hit the rate limits together.

## Other Things to Know

- **Database tables** are created and updated automatically when the API starts. You only need an empty database.
- **Roles** (`ADMIN`, `USER`, `GUEST`) are created on the first start. No admin account is created; see [Creating the First Admin](./first-admin.md).
- **Health check:** `GET /actuator/health` is public and returns `"status":"UP"` when the API is running. The Docker image uses it as its health check.
- **Swagger UI** at `/swagger-ui.html` and the OpenAPI description at `/v3/api-docs` are public, so anyone who can reach the API can see the list of endpoints.
- **Download records** keep the IP address of the player who downloaded, and they are not deleted automatically. If your game is subject to privacy rules (like GDPR), mention it in your privacy policy.
- **Debug logs** are off. To turn them on while developing, set `LOGGING_LEVEL_ORG_SPRINGFRAMEWORK_SECURITY=DEBUG` (security logs) or `SPRING_JPA_SHOW_SQL=true` (SQL queries).
